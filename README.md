# StudyHub - 학생을 위한 스터디 모임 플랫폼

서울사이버대학교 UI/UX프로그래밍 실습 과제 프로젝트입니다.

- **배포 주소**: https://svelion.github.io/scu-web-service-page/
- **기술 스택**: HTML5, CSS3, JavaScript (Vanilla)

## 사용자와 서비스 목적

- **주요 사용자**: 혼자 공부가 막막해 함께 공부할 동료가 필요한 대학생
- **서비스 목적**: 같은 목표를 가진 학생들이 스터디 모임을 쉽게 만들고 참여할 수 있게 한다
- **핵심 행동**: 스터디 모임 개설 (7주차) / 스터디 참여 신청 폼 (9주차 개편) / 내비게이션과 목록 탐색 (10주차)

## 10주차 구현: 내비게이션 UI와 정보 탐색

메뉴 이동 경로, 현재 위치 표시, 목록 필터와 결과 안내, 모바일 메뉴를 추가했습니다.

### 이번 주 추가·수정한 기능

| 기능 | 내용 |
|------|------|
| 메뉴 구조 | 상단 메뉴를 `nav > ul > li` 구조로 구성. 7개 메뉴(서비스 소개/주요 기능/이용 방법/모임 개설/내 모임/스터디 가이드/참여 신청)의 이름과 목적지(`#id`)가 일치 |
| 현재 위치 표시 | 현재 보고 있는 섹션의 메뉴에 흰 배경·볼드 강조와 `aria-current="true"`를 함께 적용. 메뉴 클릭, 스크롤 이동, 새로고침, 뒤로 가기 이후에도 표시가 실제 위치와 일치 |
| 목록 필터 | "내 모임"에 상태 필터 버튼 3가지(전체 / 운영 중 / 취소됨) 추가. 선택 버튼의 표시와 `aria-pressed`가 함께 변경되고, 기존 과목 검색(찾기)과 조합해 동작 |
| 결과 안내 | "총 N개의 모임 중 M개 표시 중" 문구로 현재 표시 개수를 안내(`aria-live`). 모임이 아예 없는 경우("아직 개설한 모임이 없습니다")와 조건에 맞는 결과만 없는 경우("'○○' 과목 + '운영 중' 상태에 해당하는 모임이 없습니다 + 필터를 전체로 풀기")를 구분해 안내 |
| 모바일 메뉴 | 좁은 화면(768px 이하)에서 "메뉴 열기" 버튼으로 메뉴 펼침/접힘. 실제 표시(`.is-open`), 버튼 문구("메뉴 열기/닫기"), `aria-expanded`가 항상 같이 변경. 메뉴에서 목적지를 선택하면 이동 후 메뉴가 닫히고, 화면이 넓어지면 메뉴가 항상 표시됨 |
| 전체 흐름 | 기존 기능(모임 개설 마법사, 내 모임 검색/취소, 가이드 탭, 참여 신청 폼)은 그대로 유지되며 PC/모바일 모두 동작 |

### 메뉴별 목적지

| 메뉴 | 목적지 | 내용 |
|------|--------|------|
| 서비스 소개 | `#intro` | StudyHub 소개 |
| 주요 기능 | `#features` | 검색·개설·출석 기능 카드 |
| 이용 방법 | `#howto` | 3단계 이용 순서 |
| 모임 개설 | `#create` | 5단계 개설 마법사 |
| 내 모임 | `#mylist` | 개설 모임 목록 + 상태 필터 + 과목 검색 |
| 스터디 가이드 | `#tips` | 참여 팁/개설 가이드/FAQ 탭 |
| 참여 신청 | `#join` | 참여 신청 폼 |

### 필터 기준

- 상태: 전체 / 운영 중 / 취소됨 (모임 취소 시 카드가 사라지지 않고 "취소됨" 상태로 남음)
- 과목: 전체 과목 / 자료구조 / 데이터베이스 / UI/UX프로그래밍 / 파이썬프로그래밍 / 기타 (상태 필터와 동시 적용)

### 확인 순서 (브라우저에서 직접 테스트)

1. 메뉴 "내 모임" 클릭 → 해당 메뉴만 흰 배경·볼드로 강조되고 `aria-current="true"` 확인
2. 스크롤을 다른 섹션으로 이동 → 현재 위치 강조가 스크롤 위치를 따라 바뀌는지 확인
3. 새로고침과 뒤로 가기 이후에도 강조가 주소 해시와 일치하는지 확인
4. 모임을 2개 개설 후 하나 취소 → "총 2개의 모임 중 2개 표시 중"에서 상태가 [취소됨/운영 중]으로 표시되는지 확인
5. "취소됨" 필터 클릭 → 취소한 모임만 보이고, 버튼 강조와 `aria-pressed="true"`가 함께 바뀌는지 확인, "운영 중" 필터도 반대로 확인
6. "운영 중" + "자료구조" 과목 검색 (취소된 자료구조 모임만 있을 때) → "0개 표시 중" + 조건을 명시한 빈 결과 안내 + "필터를 전체로 풀기" 버튼 동작 확인
7. 창을 390px로 좁히면 → "메뉴 열기" 버튼 표시, 메뉴 접힘. 버튼 클릭 시 메뉴가 펼쳐지고 문구가 "메뉴 닫기"로 바뀌며 `aria-expanded="true"` 확인
8. 모바일 메뉴에서 "모임 개설" 클릭 → 해당 위치로 이동하고 메뉴가 닫히며 문구·`aria-expanded`가 함께 복귀하는지 확인
9. 창을 1280px로 넓히면 → 토글 없이 메뉴가 항상 표시되는지 확인
10. 기존 기능(개설 마법사, 자세히 보기/취소, 탭, 참여 신청 폼 검증·제출)이 PC/모바일에서 그대로 동작하는지 확인

## 9주차 구현: 폼 UI와 입력 경험 설계 (참여 신청 폼 전면 개편)

5주차에서 만든 참여 신청 폼을 라벨·도움말·조건부 입력·실시간 피드백·제출 상태 처리를 갖춘 폼으로 개편했습니다.

### 이번 주 추가·수정한 기능

| 기능 | 내용 |
|------|------|
| 폼 구성 | 이름(텍스트), 학교 이메일(이메일), 관심 과목(선택), 참여 동기(여러 줄) 입력. 모든 입력에 `label for` 연결 + 도움말 문구(`.field-help`) 표시 |
| 조건부 입력 | "온라인으로 참여" 체크박스 선택 시 화상 도구 선택 영역이 나타나고 활성화됨. 체크 해제/숨김 상태에서는 `disabled`로 비활성화하고 값도 초기화 |
| 입력 검증 | 이름 빈 값, 이메일 형식(정규식), 관심 과목 선택, 참여 동기 10자 이상, 온라인 참여 시 도구 선택까지 검사 |
| 실시간 피드백 | 참여 동기 입력 중 글자 수 카운터(`0 / 10자`)가 실시간으로 갱신되고, 10자 충족 시 초록색 "조건을 충족했어요"로 전환 |
| 오류 피드백 | 조건 미충족 시 항목별로 "무엇이 문제이고 어떻게 고치는지" 문구로 안내(색상+문구 이중 구분). 입력을 수정하면 `input`/`change` 이벤트에서 즉시 오류가 해제됨 |
| 제출 처리 | `submit` 이벤트로 처리. 미충족 시 제출 차단 + 첫 오류 항목으로 포커스 이동. 제출 중에는 "저장하는 중..." 진행 문구 + 버튼 비활성화(중복 제출 방지). 성공 시 브라우저(`localStorage`)에 저장하고 완료 안내, 실패 시 입력을 유지한 채 "다시 시도하기" |
| 다시 작성 | "다시 작성" 버튼으로 입력값, 오류 문구, 조건부 영역, 카운터, 버튼 상태가 함께 초기화 |

### 입력 조건 요약

- 이름: 필수, 빈 값 불가
- 학교 이메일: 필수, `@`와 `.`이 포함된 이메일 형식
- 관심 과목: 필수, 목록에서 선택
- 참여 동기: 필수, 공백 제외 10자 이상
- 화상 도구: "온라인 참여" 체크 시에만 표시되며 그때는 필수

### 확인 순서 (브라우저에서 직접 테스트)

1. 아무 것도 채우지 않고 "스터디 참여 신청하기" 클릭 → 제출이 막히고 이름부터 항목별 빨간 안내 문구 표시, 이름 입력창으로 포커스 이동 확인
2. 이메일에 "abc" 입력 후 다시 제출 → "이메일 형식이 아닙니다" 문구 확인
3. 참여 동기에 3자만 입력 → 카운터가 "3 / 10자 - 아직 부족해요"(주황)로 표시되는지 확인
4. 참여 동기를 10자 이상 입력 → 카운터가 즉시 초록색 "조건을 충족했어요"로 바뀌고 동기 오류 문구가 사라지는지 확인
5. 이름/이메일을 고치는 순간 해당 오류 문구가 즉시 해제되는지 확인
6. "온라인으로 참여" 체크 → 화상 도구 영역이 나타나고 선택 가능해짐. 체크 해제하면 영역이 숨겨지고 값 초기화 확인. 체크한 상태에서 도구 미선택 제출 → 도구 오류 문구 확인
7. 모든 조건 채운 뒤 제출 → 버튼이 "저장하는 중..."으로 바뀌고 비활성화(연속 클릭 무시), 이후 초록 완료 안내 + "신청 완료" 버튼 확인
8. "다시 작성" 클릭 → 입력값, 오류 문구, 조건부 영역, 카운터, 버튼이 모두 초기화 확인

## 6주차 구현: 이벤트 처리와 동적 UI (스터디 가이드 탭)

### 구현한 이벤트

| 이벤트 | 대상 | 화면 변화 |
|--------|------|-----------|
| click | 스터디 가이드 탭 버튼 3개 | 선택된 탭 버튼의 배경색/글자색/테두리가 활성 스타일로 바뀌고(스타일), `aria-selected`가 갱신되며(상태), 해당 탭의 콘텐츠만 표시되고 나머지는 숨겨진다(문구 교체) |
| input | 참여 신청 폼 이메일 입력(5주차) | 오류 문구 제거 + 버튼 상태 자동 복구 |
| input | 모임 개설 이름/소개 입력(7주차) | 필드 안내 숨김 + 붉은 강조 해제 |
| change | 모임 개설 과목 select/요일 radio(7주차) | 선택값 저장 + 오류 문구 숨김 + 강조 해제 |

탭 구성: "참여 팁" / "개설 가이드" / "자주 묻는 질문" 3개. 선택된 탭은 진한 파란 배경으로 구분되며, 선택되지 않은 탭의 콘텐츠는 `hidden` 속성으로 완전히 숨겨진다.

### 화면 너비 테스트 (1100px / 768px / 390px)

| 너비 | 확인 결과 |
|------|-----------|
| 1100px | 탭 3개가 한 줄에 표시되고 클릭 시 콘텐츠 전환 정상 |
| 768px 이하 | 탭 버튼이 세로로 쌓이고 전체 폭이 되어 잘리지 않음, 전환 정상 |
| 390px | 모임 개설 버튼 세로 배치, 요약표 세로 정렬, 가로 스크롤 없이 조작 가능 |

## 7주차 구현: 스터디 모임 개설 흐름

- **사용자**: 새 스터디 모임이 필요한 대학생
- **사용자 목표**: 나만의 스터디 모임을 개설하는 것
- **핵심 행동**: 모임 정보 입력 - 일정 선택 - 개설 확정
- **완료 조건**: 완료 화면에 모임 이름과 개설 정보가 표시된다

### 사용자 흐름 (5단계)

```
1. 시작       : 모임 개설 안내 확인 후 "모임 개설 시작하기" 클릭
2. 정보 입력  : 모임 이름(필수), 한 줄 소개(필수) 입력
3. 일정 선택  : 주요 과목(필수), 모임 요일(필수), 모집 인원(선택) 지정
4. 확인       : 입력 내용 요약 확인, "수정하기"로 돌아가 고치기 가능
5. 완료       : 개설 완료 메시지와 최종 모임 정보 표시, "다시 만들기"로 초기화
```

### 인터랙션 시나리오 (행동 - 이벤트 - 조건 - 화면 반응 - 다음 상태)

| # | 행동 | 이벤트 | 조건 | 화면 반응 | 다음 상태 |
|---|------|--------|------|-----------|-----------|
| 1 | "모임 개설 시작하기" 클릭 | click | 조건 없음 | 2단계 패널 표시, 진행바 "정보 입력" 활성화 | 2단계 |
| 2 | "다음: 일정 선택" 클릭 | click | 모임 이름 비어 있음 | 이름 입력창 붉은색 강조 + 필드 안내 + 단계 오류 문구, 포커스 이동 | 2단계 유지 |
| 3 | "다음: 일정 선택" 클릭 | click | 이름 비어 있지 않음, 소개 비어 있음 | 소개 입력창 강조 + 오류 문구, 포커스 이동 | 2단계 유지 |
| 4 | "다음: 일정 선택" 클릭 | click | 필수값 모두 입력됨 | 3단계 패널 표시, 진행바 "일정 선택" 활성화 | 3단계 |
| 5 | "다음: 확인" 클릭 | click | 과목 미선택 | 과목 select 강조 + 오류 문구 | 3단계 유지 |
| 6 | "다음: 확인" 클릭 | click | 요일 미선택 | 요일 그룹 강조 + 오류 문구 | 3단계 유지 |
| 7 | "다음: 확인" 클릭 | click | 과목/요일 선택됨 | 확인 화면에 저장된 값 요약 표시 | 4단계 |
| 8 | "수정하기" 클릭 | click | 조건 없음 | 이전 단계 패널 표시, 입력값 그대로 유지 | 3단계 (값 보존) |
| 9 | 값 수정 후 "다음: 확인" 재클릭 | input/change 후 click | - | 요약이 최신 값으로 갱신됨 | 4단계 |
| 10 | "개설 확정" 클릭 | click | 조건 없음 | 완료 화면 표시 + 모임 이름/정보 표시 | 5단계 (완료) |
| 11 | "다시 만들기" 클릭 | click | 조건 없음 | 입력, 선택, 오류 문구, 진행 표시 모두 초기화 | 1단계 |

### 오류 처리

- 필수 입력(모임 이름, 한 줄 소개)이 비어 있으면 다음 단계로 이동하지 않고,
  해당 입력창을 붉게 강조하고 무엇을 어떻게 고쳐야 하는지 화면에 안내한다.
- 필수 선택(주요 과목, 모임 요일)이 누락되면 같은 방식으로 안내하고 현재 단계를 유지한다.
- "수정하기"로 이전 단계에 돌아가도 값이 유지되고, 수정 후 확인 화면에 다시 반영된다.
- "다시 만들기"를 누르면 입력값, 선택값, 오류 문구, 진행 표시가 모두 초기화된다.

## 5주차 구현: 스터디 참여 신청 폼

- 이름/이메일 빈 값 검사, 이메일 형식 검사(정규식)
- 오류 시 경고 문구, 성공 시 완료 문구 + 버튼 상태 변경
- 입력 재개 시 버튼 상태 자동 복구

## 4주차 구현: 반응형 웹

- viewport 메타 태그
- 기능 카드 CSS Grid (`auto-fit`, `minmax`)
- 768px 이하 미디어 쿼리: 내비게이션 세로 배치, 카드 1열, 버튼 전체 폭

## 중간시험 구현: 내 모임 목록 (저장 / 검색 / 취소)

7주차 결과물에서 추가한 내용: 개설을 완료한 모임을 "내 모임" 목록에 저장하고, 과목으로 찾아보고, 목록에서 다시 열어 보거나 취소할 수 있는 기능.

### 사용자 행동 → 조건 → 반응

| 사용자 행동 | 확인할 조건 | 성공 반응 | 오류 / 결과 없음 / 취소 반응 | 다음 행동 |
|-------------|-------------|-----------|------------------------------|-----------|
| 5단계에서 "개설 확정" 클릭 | 4단계 확인 통과 | 완료 화면 표시 + "내 모임" 목록에 카드 자동 저장 | - | 완료 화면 확인, 목록으로 이동 |
| "찾기" 클릭 (과목 선택) | 해당 과목 모임 존재 | 해당 과목 카드만 표시 | - | 카드에서 자세히 보기/취소 |
| "찾기" 클릭 (과목 선택) | 해당 과목 모임 없음 | - | "○○ 과목으로 개설한 모임이 없습니다" 안내 | "새로 개설하거나" 링크 또는 "전체 모임 보기" 버튼 |
| "자세히 보기" 클릭 | 항목 접힘 상태 | 한 줄 소개/과목/요일/인원 상세 펼침 | - | 다시 클릭하면 접힘(토글) |
| "모임 취소" 클릭 | 확인 대화상자 "확인" | 카드가 취소 상태로 변경(취소됨 배지, 제목 취소선, 상세 열림) | 대화상자 "취소" 시 아무 변화 없음 | 필요하면 새 모임 개설 |

- 취소된 모임은 목록에서 사라지지 않고 "취소됨" 상태로 남아 무엇이 취소되었는지 확인할 수 있다.
